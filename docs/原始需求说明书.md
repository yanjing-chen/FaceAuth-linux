# FaceAuth 开发需求说明书

> 面向从零开始开发的 AI / 工程师。本文自包含，是一份完整的需求与规格说明，无需任何历史背景。
> 目标：在 Linux（Ubuntu / GNOME / Wayland）上做一套**可发布**的人脸认证系统，最终能用于 **图形登录 / sudo / polkit 授权**，且密码永远兜底、绝不锁死用户。

---

## 1. 项目目标与范围

### 1.1 要解决什么问题

Linux 上缺少一个安全、可靠、不联网、不锁死系统的人脸认证方案。howdy 类项目因为提权和 PAM 挂载方式的问题口碑不佳。本项目要做的是：

- 本地识别：**不联网、不上传、不存原始照片**（只存 128 维特征向量）。
- 用于 **sudo 提权、GDM 图形登录 / 锁屏、polkit 授权（synaptic / 磁盘设置等弹框）**，可扩展 su / TTY login。
- 安全：内存安全的核心、fail-safe 回退、可对抗照片 / 屏幕 / 平面面具（依硬件等级）。
- 发布级：任何 V4L2 摄像头都能用，支持单 HD / 单 IR / 双模 / ToF 深度，支持一人多脸。

### 1.2 必须避开的两个前提（用户核心关切）

1. **不重蹈 howdy 的覆辙**：
   - 坑一：**GUI 提权**（pkexec/elevate）导致环境变量丢失、画面出不来；
   - 坑二：**刷脸模块挂进 `/etc/pam.d/common-auth`**，波及 polkit 授权，触发摄像头死锁 / 系统卡死。
2. **项目是要发布的，不能绑定某一台单机**：硬件走标准 V4L2，配置用路径 + 开关，换摄像头 / 换机器不用改代码。
3. **GUI 必须是 GNOME 原生风格**（GTK4 + libadwaita），走 Wayland 原生，不退回 X11。

### 1.3 设计原则（不可妥协）

1. **密码永远是 fallback**。任何异常（摄像头占用、模板损坏、推理超时、daemon 挂掉、未配置）都必须回退到系统原有的密码 / 指纹，绝不把用户锁在系统外。
2. **PAM 模块纯净**：纯 Rust cdylib、零依赖、不 fork 子进程、不加载 Python、不碰 DISPLAY/WAYLAND 等图形环境。
3. **权限最小化**：GUI / CLI 以普通用户运行、不提权；摄像头 / 推理器 / 模板由 root daemon 独占；socket 用 `SO_PEERCRED` 校验调用者 uid。
4. **只挂指定 PAM 服务**：绝不写 `common-auth` / `other`。

### 1.4 明确不做 / 诚实声明

- 人脸认证是**便利性增强，不是强密码替代品**。
- 对标 Windows Hello 的四层防伪（主动 IR + 3D 深度 + 材质光谱 + 动态活体 + TPM）：本项目覆盖 IR 成像 + 3D 深度几何（需硬件）+ 部分启发式活体，**不覆盖材质光谱、无 TPM 绑定、未过 ISO/IEC 30107-3**。防得住照片 / 屏幕 / 平面面具（有深度时），防不住高仿 3D 面具与胁迫解锁。发布文档必须如实告知。

## 2. 技术选型

| 层 | 选型 | 原因 |
|---|---|---|
| PAM 模块 | **纯 Rust cdylib** | 必须内存安全、零依赖、不 fork；Python 进 PAM 会重演 howdy 的环境变量/死锁坑 |
| 核心库 / daemon | **Rust** | 独占设备、socket、uid 校验、fail-safe，编译成静态二进制 |
| 推理器 | **独立 Python 进程** | 该环境装不了 Rust 的 ML crate（onnxruntime / opencv）；用行协议隔离，可替换成任意语言 |
| GUI | **Python + PyGObject GTK4 + libadwaita** | GNOME 原生风格 |
| 认证模型 | OpenCV YuNet（检测）+ SFace（128 维特征），ONNX 权重随包 | 现成可用、纯 CPU |

**关键取舍**：PAM/daemon 与 Python 之间用 **Unix socket + 行协议** 隔离，Python 只做「给定一个灰度帧，返回特征 / 活体分数」，绝不进入认证关键路径的决策。

## 3. 整体架构

```
                        ┌──────────────────────────────────────┐
   PAM (sudo/gdm/       │  root daemon  (独占摄像头/推理器/模板) │
   polkit/su/login) ────┤  Unix socket: /run/faceauth/daemon.sock│
   纯 Rust cdylib       │  SO_PEERCRED 校验 uid                 │
        │               │  模板: /var/lib/faceauth/models/<u>.bin│
        │ AUTH <user>   └───────┬──────────────────────────────┘
        │                       │ spawn/复用 → 行协议 → infer_engine.py
        │                       │                  YuNet + SFace (ONNX)
        ▼                       ▼
   PAM_IGNORE /        ┌────────────────────────┐
   PAM_SUCCESS         │ 摄像头: HD / IR / 深度   │  ← V4L2，配置路径，不绑定机型
                       └────────────────────────┘

   用户态 GUI (GTK4, 不提权) ──ENROLL_AS / DELETE_FACE / LIST / TEST / SCENE_*──> 同一个 daemon
```

- **只有 `AUTH` 允许 root（uid 0）调用**（PAM 以 root 发）；其它命令都要求「调用者本人 = 目标用户」。
- daemon 一次认证：读配置 → 按 mode 选设备 → 抓帧 → 提特征 → 与该账户所有脸比对取最高分 → 双模走 IR 活体 → 有深度走 depth3d → 返回 OK / DENIED / IGNORE。
- PAM 模块只认 `OK`（→ PAM_SUCCESS），其它一律 PAM_IGNORE 回退密码。

## 4. 分阶段开发需求

### M1 — 核心认证链路

1. Rust workspace：`src/core`（库）、`src/pam`（cdylib）、`src/daemon`、`src/cli`，`resolver=2`，release profile `opt-level="z"`, `lto=true`, `strip=true`, `panic="abort"`。
2. `core/capture.rs`：用 V4L2 抓一帧，灰度化，带超时（3s）；不依赖图形栈。
3. `core/store.rs` / `face_store.rs`：模板存储，**v2 格式支持一人多脸**（label + embedding），兼容旧 v1 单模板；文件含校验和，损坏即 fail-closed；目录 0700、文件 0600。
4. `daemon`：Unix socket `/run/faceauth/daemon.sock`（0666 + SO_PEERCRED 校验），命令见 §5.4。
5. `pam`：手写 FFI（`pam_get_user` / `pam_syslog`，避免 pam-sys 依赖），5s 读写超时，异常全 PAM_IGNORE。
6. 用**独立 PAM 测试栈** `faceauth-test`（认证成功才过，否则 pam_permit 兜底）+ `pamtester` 端到端验证，绝不拿真实服务做实验。
7. 编译用普通用户，避免 root 生成文件污染仓库。

### M2 — 推理器与活体

1. `scripts/infer_engine.py`：独立进程、行协议（见 §5.6）。程序启动先 import cv2 再就绪，靠 PING/PONG 握手解决 import 慢导致的 BrokenPipe。
2. 模型路径相对项目根：`assets/models/face_detection_yunet_2023mar.onnx`、`face_recognition_sface_2021dec.onnx`。
3. IR 灰度图喂 YuNet 前先 `GRAY2BGR`，否则崩溃。
4. 活体三级：`none` / `heuristic`（IR 启发式，抗照片屏幕）/ `depth3d`（+ 深度几何，抗平面面具）。请求 depth3d 但没配 depth_device 时**自动降级为 heuristic**，不锁死旧机器。
5. 深度设备支持 `Z16` / `Y16` / `Y12` 等 16bit/12bit V4L2 深度格式，不依赖厂商 SDK；平面拒绝、球面接受。

### M3 — GUI + 多脸 + 场景挂载

1. GTK4 + libadwaita GUI：圆形取景框、人脸框、采集引导、模式 / 活体 / 设备下拉、人脸列表、单个删除、识别测试。
2. 一人多脸：GUI 显示已录人脸列表，可分别录入 / 单独删除。
3. **适用场景开关**：sudo / 图形登录（gdm）/ su / TTY login / polkit，用户可在 GUI 里开关（后端见 §5.5）。
4. **识别测试按钮**：用当前录入模式现场抓帧比对，返回 OK/DENIED/IGNORE + 详情（mode/sim/face/result），供用户自助验证。
5. 硬件 / 安全文档（`README.md` / `SECURITY.md` / `HARDWARE.md`）随包发布。

### 4.1 三种摄像头工作模式（录入与认证共用）

要求支持**三种模式**，GUI 下拉与配置 `mode` 一一对应：

| 模式 | 配置值 | 用哪个摄像头 | 取景 / 检测 / 提特征 | 活体 | 安全性 |
|---|---|---|---|---|---|
| **单 HD（彩色）** | `mode=rgb` | 仅彩色 HD 摄像头（`rgb_device`） | 全部走彩色帧 | 无 IR 活体；`heuristic` 退化为图像纹理判断，效果有限 | 低，可被照片骗 |
| **单 IR（红外）** | `mode=ir` | 仅红外摄像头（`ir_device`） | 全部走 IR 帧；IR 灰度图须先 `GRAY2BGR` 再喂 YuNet | IR 启发式（`heuristic`） | 中，抗照片/屏幕 |
| **双模（HD+IR）** | `mode=dual`（默认） | 彩色 HD + 红外两个节点 | **识别特征取彩色帧**（`rgb_device`），取景框显示彩色 | **活体取 IR 帧**（`ir_device`），分数 ≥0.5 才计数 | 中/高，追加深度时更高 |

**"HD 摄像头"就是普通彩色高清 USB 摄像头**（RGB/BGR，V4L2，如 `/dev/video0`），区别于红外摄像头。GUI 抓一帧判类型：**BGR 通道差 > 2 → 彩色 HD，否则 → IR**，在设备列表里标注「彩色 HD」/「红外 IR」，用户分别下拉选择。`depth3d` 另需第三个输出深度格式（Z16/Y16/Y12）的节点。

**独立的 HD 摄像头 + 独立的 IR 摄像头（两个不同 USB 口）必须能工作，且不绑定同一复合模组。**
- 代码**不假定** HD 与 IR 是同一物理模组，而是靠 `rgb_device` / `ir_device` 两个独立配置项分别指定各自的 `/dev/v4l/by-id/` 路径。
- 双模只要求两个节点都可见、能被同时打开：两个独立 USB 摄像头天然满足；复合模组是其两个 V4L2 节点，同样满足。
- 录入 / 认证逻辑对两种接法完全一致，**换设备只改配置 + 重新录入，不改代码**。
- 注意：**IR 特征与 RGB 模板不通用**。用单 IR 或双模录入的模板不能在单 HD 模式下认证；切换模式必须重新录入。

**录入流程（三种模式共用）**：目标人脸出现后连续采 **5 帧**；双模每帧先过 IR 活体再计数；每帧经 YuNet 检测 → `alignCrop` → SFace 提 128 维特征；5 帧取**平均后 L2 归一化**；用 `ENROLL_AS <user> <label> <hex>` 发给 daemon 存成具名脸。阈值默认 `threshold=0.6`。

## 5. 各模块详细需求（接口精确定义）

### 5.1 `src/core`（Rust 库）
- `config.rs`：解析 `~/.config/faceauth/config`，字段见 §5.7；`effective_liveness()` 实现 depth3d 优雅降级。
- `infer.rs`：`InferBackend` 抽象，方法 `embed` / `liveness` / `detect` / `depth3d`；`ExternalBackend` 用行协议驱动外部推理器，带 PING 握手。
- `liveness.rs`：`DepthFrame`（解析 Z16/Y16/Y12）+ `verify_depth_3d`（平面拒绝 / 球面接受）。
- `face_store.rs`：v2 多脸结构（`Face { label, embedding }`），`put/replace/remove/best_match/labels`，兼容 v1。
- `scene.rs`：场景挂载管理，见 §5.5。
- 单元测试覆盖：配置解析、模板读写、活体几何、场景白名单。

### 5.2 `src/pam`（PAM 模块）
- 导出 `pam_sm_authenticate` / `pam_sm_setcred` / `pam_sm_acct_mgmt`（后两个返回 PAM_IGNORE）。
- `pam_get_user` 取用户名（不硬编码）；连 socket 发 `AUTH <user>\n`，5s 超时。
- 响应：`OK`→PAM_SUCCESS；`DENIED`/`IGNORE`/`ERR`/异常→PAM_IGNORE。
- 结果写 journald（`pam_syslog`），不写人脸数据。

### 5.3 认证判定 `authenticate()`（daemon 内，AUTH 与 TEST 共用）
- 读目标用户配置，按 mode 选设备（ir 模式用 ir_device，其余优先 rgb_device）。
- 读模板（空则 IGNORE）；启动推理后端；抓帧 3s 超时 → 灰度 → embed。
- 与所有脸 `best_match`，`sim < threshold` → DENIED。
- 若配了 ir_device → IR 活体分数 < 0.5 → DENIED。
- 若 `effective_liveness().needs_depth()` 且配了 depth_device → 从 IR 帧检测人脸框（失败用居中区域兜底）→ 抓深度帧 → `depth3d` < 0.5 → DENIED。
- 详情串格式：`mode=<m> sim=<s> face=<label> result=<accepted|mismatch>`。

### 5.4 `src/daemon` socket 命令（行协议，一行一请求一行响应）

| 命令 | 权限 | 响应 |
|---|---|---|
| `PING` | 任意 | `PONG` |
| `AUTH <user>` | **仅 uid 0** | `OK` / `DENIED` / `IGNORE` |
| `TEST <user>` | 本人 | `<verdict> <detail>` |
| `ENROLL <user> <hex>` | 本人 | `OK enrolled:default`（兼容旧调用） |
| `ENROLL_AS <user> <label> <hex>` | 本人 | `OK enrolled:<label>` |
| `DELETE <user>` | 本人 | `OK deleted` / `OK no model` |
| `DELETE_FACE <user> <label>` | 本人 | `OK deleted` / `OK no such face` |
| `LIST <user>` | 本人 | `OK <n> <label1,label2,...>` / `OK 0` |
| `SCENE_LIST <user>` | 本人 | `OK sudo:1,gdm:0,su:0,login:0,polkit:0` |
| `SCENE_ON <user> <scene>` / `SCENE_OFF <user> <scene>` | 本人 | `OK <msg>` / `ERR <msg>` |

- `<hex>` 是 128 个 f32 的小端 hex（每 f32 8 个 hex 字符，共 256 字符）；daemon 端校验并解码。
- 所有「本人」命令用 `is_self(peer_uid, user)`（查 /etc/passwd）校验；不匹配返回 `ERR ... peer uid mismatch`。
- daemon 启动时建 `/run/faceauth`、`/var/lib/faceauth/models`（0700），删旧 socket 再 bind。

### 5.5 场景挂载 `scene.rs` + GUI 开关（最终要打通的目标）

- **白名单**（不接受任意路径，防路径穿越）：

| id | 说明 | PAM 服务文件 |
|---|---|---|
| `sudo` | 终端提权 | `/etc/pam.d/sudo` |
| `gdm` | 图形登录 / 锁屏 | `/etc/pam.d/gdm-password` |
| `su` | 切换用户 | `/etc/pam.d/su` |
| `login` | TTY 文本登录 | `/etc/pam.d/login` |
| `polkit` | 图形授权（synaptic/磁盘设置等） | `/etc/pam.d/polkit-1` |

- 挂载行（**必须**含 `default=ignore`，禁止 required/requisite；模块路径按目标架构/发行版调整）：
  `auth    [success=done default=ignore]    /usr/lib/<arch>/security/pam_faceauth.so`
- 插入位置：`@include common-auth` 之前；找不到则追加末尾。
- **polkit 特殊处理**：多数系统 `/etc/pam.d/polkit-1` 默认不存在（polkit 回退到 `other`→`common-auth`）。启用时**新建该文件**，内容：
  ```
  # FaceAuth: 图形授权
  auth    [success=done default=ignore]    .../pam_faceauth.so
  @include common-auth        ← 关键：回退到系统链（指纹 + 密码），不锁死
  @include common-account
  ```
  禁用时若文件内容等于该模板则删除整个文件，干净回退到系统默认。
- 所有改动前备份到 `/var/lib/faceauth/backups/`，可回滚；`enable/disable` 幂等。
- **红线**：绝不写 `common-auth` / `other`；接入前必须确认 pam 模块 `.so` 已安装。

### 5.6 `scripts/infer_engine.py` 行协议

```
输入（stdin 每行一条）：
  PING                                    → PONG            （就绪握手，必须最先做）
  EMBED <w> <h> <hex_gray>                → OK <128×f32 小端 hex>   （SFace 特征）
  LIVENESS <w> <h> <hex_gray>             → OK <score 0~1>   （IR 启发式活体）
  DETECT <w> <h> <hex_gray>               → OK <x> <y> <bw> <bh>  （YuNet 人脸框）
  DEPTH <w> <h> <hex_depth16> [x y bw bh] → OK <score 0~1>   （3D 几何活体）
错误 → ERR <msg>
```
- hex 图：灰度按行优先逐字节 2 位 hex；深度按 u16 小端逐像素 4 位 hex。
- 特征 hex 须能用 `np.float32(x).tobytes().hex()` 原样还原（小端）。

### 5.7 配置项 `~/.config/faceauth/config`（0600，ini 风格 `key=value`）

```ini
mode=dual                        # rgb(单HD彩色) / ir(单IR) / dual(HD+IR双模)
rgb_device=/dev/v4l/by-id/...    # 彩色 HD 摄像头稳定路径，别用 /dev/video0
ir_device=/dev/v4l/by-id/...     # 红外摄像头稳定路径，dual/ir 模式需要
depth_device=/dev/v4l/by-id/...  # 可选，ToF/结构光，深度活体
liveness=heuristic               # none / heuristic / depth3d
threshold=0.6                    # 相似度阈值 0~1
infer_program=/abs/path/scripts/infer_engine.py
```

### 5.8 安装 / 卸载脚本
- `install.sh`：装 PAM 模块（0644 root）、daemon（0755 root）、systemd 服务（`RuntimeDirectory=faceauth`）、独立测试栈；**默认不挂任何真实服务**，挂载需显式 opt-in。
- `uninstall.sh`：删除所有挂载、daemon、模块、模板、测试栈，恢复系统干净。
- `mount-sudo.sh` / `unmount-sudo.sh`：单服务挂载 / 卸载辅助脚本。

## 6. 安全契约（红线，任何代码不得违反）

1. GUI 绝不提权，不用 pkexec/elevate。
2. 认证路径不碰图形栈，提示只走 PAM conversation 文本。
3. PAM 模块只挂指定服务，绝不写 `common-auth` / `other`。
4. 挂载行必须 `default=ignore`，失败回退密码。
5. 原始帧不落盘（GUI 显示用内存纹理或按 uid 区分的临时文件，见 §8）。
6. `AUTH` 仅 root；用户只能操作自己的模板 / 场景。
7. 每次认证有超时（抓帧 3s、socket 读写 5s）、失败 fail-safe。
8. 模板 / 配置 0600，模板带校验和，损坏 fail-closed。

## 7. 硬件兼容（发布级要求，不绑定单机）

| 硬件 | mode | liveness | 安全性 |
|---|---|---|---|
| 普通彩色 HD 摄像头（单 HD） | `rgb` | `none` / `heuristic`（有限） | 低，可被照片骗 |
| 彩色 HD + IR（同一复合模组，或**两个独立 USB 摄像头**均可） | `dual` | `heuristic` | 中，抗照片/屏幕 |
| 彩色 HD + IR + ToF/结构光 | `dual` | `depth3d` | 高，追加抗平面面具 |
| 仅 IR 摄像头（单 IR） | `ir` | `heuristic` | 中，须用 IR 重新录入（IR 与 RGB 特征不通用） |

- **三种模式 / HD 摄像头的完整定义、独立 HD+IR 接法、录入流程见 §4.1。**
- 换摄像头**必须重新录入**（模板存的是该摄像头的特征分布）。
- 用 `v4l2-ctl --list-devices` / `--list-formats` 枚举，路径用 `/dev/v4l/by-id/`。
- 设备节点编号（如 video0 / video2）因机器而异，代码不可硬编码。

## 8. 实现要点与常见陷阱

### 8.1 GUI 显示（Wayland / GTK4，务必注意）

在 Ubuntu / GNOME / Wayland 下，GTK4 取景框容易出现**窗口正常但画面空白 / 不刷新**的问题。设计时直接按下面的方式做，避免返工：

- **不要把 V4L2 抓帧 / 人脸检测放在主线程**：阻塞主线程会导致 GTK 不重绘。把采集 / 检测放后台线程，线程内生成纹理，用 `GLib.idle_add` 回主线程更新 `Gtk.Picture`。
- **渲染器**：本机 Wayland 下 GTK4 默认 GSK 渲染器可能出现画面不提交，启动器里设 `GDK_BACKEND=wayland` + `GSK_RENDERER=cairo` 可规避；保持 Wayland 原生，不要退回 X11。
- **帧图不要写 `/tmp` 固定路径**：多用户 / 提权场景下会因属主不同导致写入失败、画面空白。用内存纹理（如 `Gdk.MemoryTexture`）或按 uid 区分的文件。
- **GUI 绝不提权**；用 `Adw.AlertDialog` 做删除确认。

### 8.2 其它实现陷阱

- `infer_engine.py` 里模型路径按 `__file__` 算（脚本在 `scripts/`，模型在项目根 `assets/models`），别按 cwd。
- Python import cv2 慢 → BrokenPipe：必须先 PING/PONG 握手再发真命令。
- IR 灰度图直接喂 YuNet 会崩：先 `GRAY2BGR`。
- 活体检测要用实际帧的 w/h，不要硬编码尺寸。
- 模板 hex 字节序：用 `np.float32(x).tobytes().hex()`（小端），别用 struct 大端。
- `Adw.AlertDialog.choose` 的回调 `res` 是 `Gio.AsyncResult`，必须 `dialog.choose_finish(res)` 才能拿到选择结果。
- 场景命令受 uid 校验：用本人 shell 发（`runuser -u <user>` 或普通用户终端），不要用 root 身份发。
- 编译用普通用户，避免 root 生成文件污染仓库。

## 10. 开发顺序建议

1. **先搭核心认证链路**（§4 M1 + M2）：Rust core / daemon / pam + Python 推理器，用独立 PAM 栈验证「刷脸成功、失败回退」。
2. **再做 GUI**（§4 M3 + §8.1）：GNOME 原生取景框 / 录入 / 删除 / 识别测试，注意后台线程与 cairo 渲染要点，保证普通用户可用。
3. **再做场景开关与挂载**（§5.5）：sudo / gdm / polkit，**改 PAM 前先开一个 root shell 保底**。
4. **最后做硬件兼容与发布文档**（§7 + §9.2）。

> 核心原则：**每一层都保持 fail-safe —— 任何环节失败都回退密码，绝不把用户锁在系统外。**
