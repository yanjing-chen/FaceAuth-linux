# sudo/GDM/polkit 安全实测顺序（Ubuntu/GNOME/Wayland）

## 前提
- v0.1.6 开发 GUI 能预览、录入，`faceauth-cli --dev TEST "$USER"` 返回 `OK mode=... result=accepted`。
- 先运行 `bash scripts/auth-preflight.sh`（只读），确认旧 FaceAuth 的 PAM 是否仍然启用。旧模块若存在，不得直接叠加两个模块。
- 在实机执行 `cargo test --workspace` 和 `cargo build --release --workspace` 后再考虑部署；脚本不能代替这些验证。

## 安全的系统部署阶段
1. 先关闭开发版 GUI/daemon，不允许两个服务同时占用摄像头。
2. 使用 `sudo bash scripts/install-system.sh` 安装**独立**服务（默认不挂任何真实 PAM）。再次运行 `bash scripts/auth-preflight.sh`。
3. 生产 GUI `bash scripts/launch-gui.sh` 重新录入新服务的人脸（开发与系统模板不通用）。
4. 生产模式下以普通用户运行 `target/release/faceauth-cli TEST "$USER"`，必须返回 `OK`（不是 `IGNORE` 或 `DENIED`）。
5. **单独 PAM 测试栈**：`sudo pamtester faceauth-linux-test "$USER" authenticate`。这里要用 sudo 才会以 root UID 向 daemon 发送 `AUTH`；并分别确认刷脸和密码回退。注意最终成功不一定来自刷脸，尤其是输入过密码时。
6. 确保旧版 faceauth 模块未同时挂入 `/etc/pam.d/sudo`，保留一个 `sudo -i` 管理员终端，才在 GUI 的真实场景开关启用 sudo。
7. 在另一个终端执行 `sudo -k; sudo true` 测试成功；遮挡摄像头测试密码回退；在 root 终端随时可用离线撤销工具：`/usr/libexec/faceauth-linux/faceauth-scenes off sudo`。
8. GDM/登录**最后测试**，必须先审查本机 `/etc/pam.d/gdm-password` 和所用验证方式。建议先仅锁屏测试，不要直接重启或注销当前唯一管理员会话。GNOME Keyring 可能仍需要用户密码解锁。polkit 也需单独验证密码/指纹回退，避免授权循环。

## 紧急回滚（在仍开放的 root 终端运行）
```
/usr/libexec/faceauth-linux/faceauth-scenes off sudo
/usr/libexec/faceauth-linux/faceauth-scenes off gdm
/usr/libexec/faceauth-linux/faceauth-scenes off polkit
```
**不要**自动删除现有旧版 FaceAuth PAM 配置。
